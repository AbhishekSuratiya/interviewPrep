Deep Dive Analysis

The Four Pillars of React Native Storage

Synchronous & Fast

MMKV Storage (JSI)

Multi-Map Key-Value created by WeChat. In React Native, react-native-mmkv connects directly to JS via JSI. Reads and writes run synchronously on memory-mapped files without passing through any async serialization queue.

Throughput: ~4,800 operations/ms (~50x faster than AsyncStorage). Native AES-256 encryption supported out of the box.

Hardware Encrypted

Keychain / KeyStore

Hardware-backed security utilizing iOS Secure Enclave and Android KeyStore. Keys never touch plain disk memory unencrypted. Supports biometric lockouts (Face ID / Fingerprint).

Use Case: Auth tokens, refresh tokens, private keys. Warning: Data persists across reinstalls on iOS unless explicitly cleared.

Relational & Offline-First

WatermelonDB / SQLite

For complex relational schemas (threads, comments, messages). WatermelonDB sits on SQLite and uses lazy loading — only fetching objects currently rendered on screen, keeping RAM footprint low.

Reactivity: Observable queries automatically trigger component re-renders when underlying DB records change.

Legacy / Async

AsyncStorage

The original key-value store. Asynchronous Promise-based API that serializes every object to JSON over the bridge (or async native queue). Unencrypted text files on disk.

Verdict: Legacy choice. Fine for basic demos or small projects, but replaced by MMKV in production codebases.

Interview Corrections

Common Myths & Misconceptions

"AsyncStorage is fine for storing access tokens as long as the phone has a passcode."

False. AsyncStorage writes plain text files into the app's sandboxed document directory. On rooted Android devices or backed-up unencrypted iOS devices, third-party tools or malware can inspect and extract these plain-text token files. Always use react-native-keychain for auth tokens.

"MMKV is asynchronous because disk reads take time."

False. MMKV uses mmap (memory-mapped files) to map disk files directly into virtual memory. Combined with JSI, JavaScript reads MMKV values directly in memory synchronously without await or thread switches.

"Keychain data is wiped when an iOS app is uninstalled."

False. iOS Keychain items belong to the provisioning bundle ID and persist across app uninstalls by default. If a user uninstalls and reinstalls your app, old keychain tokens remain unless you handle first-launch cleanup logic.

Senior Developer Q&A

Real-World Architectural Scenarios

💬 Question: "Your app suffers from a 100ms flash of blank content when booting because it awaits AsyncStorage to load theme preferences. How do you fix it?"
Answer: Migrate from AsyncStorage to MMKV. Because MMKV uses JSI for synchronous reads, you can read the theme setting synchronously during the initial render state setup (e.g. const [theme] = useState(() => storage.getString('theme') ?? 'light')). This eliminates the asynchronous loading spinner or blank screen flash entirely on boot.
💬 Question: "How do you implement biometric-protected login (Face ID / Touch ID) for storing a user's refreshToken?"
Answer: Use react-native-keychain with ACCESS_CONTROL.BIOMETRY_ANY_OR_DEVICE_PASSCODE. When calling setGenericPassword(), pass this access control option alongside ACCESSIBLE.WHEN_UNLOCKED_THIS_DEVICE_ONLY. When the app later calls getGenericPassword(), the OS automatically halts execution and triggers the native Face ID / Fingerprint prompt before returning the decrypted token.
