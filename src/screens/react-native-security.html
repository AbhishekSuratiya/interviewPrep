Security Architecture Pillars

Multi-Layered Client Security

Transport Layer

SSL / TLS Pinning

Pins server public key hashes (SHA-256) inside network config files or native layer. Rejects connections from proxy tools (Charles, Proxyman, Burp) even if device user installs a custom CA certificate.

Code Protection

Hermes + ProGuard / R8

Compiles JS into Hermes bytecode binary. Runs R8 code obfuscation on Android Java bytecode to rename classes and methods, preventing easy decompilation into readable source.

Runtime Environment

Root / Jailbreak Detection

Queries native OS flags via JailMonkey or custom native modules to detect Cydia, Magisk, Substrate, or ADB debugging flags, restricting sensitive financial operations.

Implementation Patterns

SSL Pinning & Jailbreak Detection Code

// 1. Jailbreak / Root detection gate
import JailMonkey from 'react-native-jailmonkey';
import { Alert, BackHandler } from 'react-native';

export function enforceDeviceSecurity() {
  if (JailMonkey.isJailBroken() || JailMonkey.hookDetected()) {
    Alert.alert(
      'Security Exception',
      'Untrusted environment detected. App closing for security.',
      [{ text: 'OK', onPress: () => BackHandler.exitApp() }]
    );
    return false;
  }
  return true;
}

Interview Pitfalls

Client Security Realities

"Client-side obfuscation makes a mobile app completely unhackable."

False. Client code runs on untrusted user hardware. Obfuscation and pinning raise the cost of reverse engineering, but true security secrets and sensitive business rules must always remain on the backend server.
