Architecture & Internals

How These Libraries Achieve 60 FPS

View Recycling

FlashList by Shopify

FlatList creates and destroys native view hierarchy instances during scrolling, consuming massive CPU cycles. FlashList recycles existing native views (leveraging Android RecyclerView and iOS UICollectionView patterns).

Result: ~10x performance boost, zero blank spaces during rapid scrolling.

Native Image Caching

FastImage

React Native's stock <Image> lacks disk caching and re-downloads remote URLs across app launches. FastImage wraps native battle-tested engines: SDWebImage (iOS) and Glide (Android).

Features: Memory + disk cache, request priority queues, image preloading, and progressive JPEG display.

UI Thread Worklets

Reanimated v3

Standard animations pass frame updates over the JS-bridge. Reanimated uses Worklets (small JS functions compiled to execute directly on the UI Thread via JSI).

Result: Animations and gestures remain locked at 60–120 FPS even when the JS Thread is 100% blocked by heavy computation.

Zero-Provider State

Zustand + MMKV

Large Context Providers trigger re-renders down the entire component subtree. Zustand uses atomic state selectors — re-rendering ONLY components subscribed to the exact changed key.

Persistence: Paired with MMKV for instant, synchronous disk persistence without Redux boilerplate.

Interview Pitfalls

Performance Myths & Misconceptions

"FlatList recycles views just like native RecyclerView on Android."

False. FlatList unmounts and mounts React components and native view instances as items enter and exit the viewport. It does NOT recycle existing view nodes. FlashList is what actually implements native view cell recycling.

"useNativeDriver: true makes all Animated API properties run on the UI thread."

False. useNativeDriver: true only supports non-layout properties like opacity and transform. It cannot animate layout properties like width, height, flex, or backgroundColor. Reanimated 3 supports layout animations on the UI thread via Worklets.

"FastImage is just a wrapper around Image with a caching header."

False. FastImage replaces the native iOS and Android image rendering pipeline completely with SDWebImage and Glide — native C++/ObjC/Java libraries that handle disk persistence, memory LRU cache, and priority queues.

Senior Technical Scenario

System Optimization Walkthrough

💬 Question: "A user reports severe scrolling lag (15–20 FPS) on a feed containing 3,000 posts with images, avatars, and interactive like animations. Walk through your step-by-step diagnostic and optimization plan."
Optimization Plan:
    Audit with React Profiler / Perf Monitor: Measure JS FPS vs UI FPS to pinpoint whether the bottleneck is on the JS thread (re-renders) or UI thread (heavy view tree). Replace FlatList with FlashList: Set estimatedItemSize={150} to enable cell recycling. This eliminates native view creation spikes during fast scrolling. Swap Image components with FastImage: Enable memory and disk caching with priority loading (priority: FastImage.priority.high for visible feed cards). Memoize List Rows: Wrap row item components in React.memo with custom comparison props, and pass callbacks wrapped in useCallback to avoid breaking row memoization. Move Like Button Animations to Reanimated v3: Convert scale/heart pop animations to useSharedValue and useAnimatedStyle so heart animations execute on the UI thread without blocking list scroll events.
