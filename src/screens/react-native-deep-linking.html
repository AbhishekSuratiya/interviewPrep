Three Types of Deep Links

Deep Link Architecture Comparison

Legacy / Basic

Custom URL Schemes

URLs starting with myapp://profile/123. Easy to implement in native manifests. However, browsers prompt a warning, and if the app isn't installed, the link simply fails without web fallback.

Modern Standard

Universal & App Links

Standard HTTPS URLs (https://myapp.com/profile/123). Verified via server configuration files (apple-app-site-association and assetlinks.json). Seamlessly opens the app if installed, or falls back to the browser website.

Deferred Attribution

Deferred Deep Links

Preserves link context when a user clicks a link before installing the app. After App Store / Play Store installation, the app reads the initial deferred link and navigates to the target content automatically.

React Navigation Setup

Configuring React Navigation Link Routing

import { NavigationContainer, LinkingOptions } from '@react-navigation/native';
import { Linking } from 'react-native';

const linking: LinkingOptions<RootStackParamList> = {
  prefixes: [
    'myapp://',
    'https://myapp.com',
    'https://www.myapp.com',
  ],
  config: {
    screens: {
      Home: '',
      Profile: 'user/:userId',
      PostDetails: {
        path: 'posts/:postId',
        parse: { postId: (id) => Number(id) },
      },
    },
  },
  async getInitialURL() {
    // Cold start link handling
    const url = await Linking.getInitialURL();
    return url;
  },
};

export default function App() {
  return (
    <NavigationContainer linking={linking}>
      {/* Screens */}
    </NavigationContainer>
  );
}
Server Verification Specs

Universal Links (AASA) & Android Asset Links

iOS AASA File

Must be served at https://myapp.com/.well-known/apple-app-site-association with application/json header.

{
  "applinks": {
    "apps": [],
    "details": [{
      "appID": "TEAMID.com.myapp",
      "paths": ["/user/*", "/posts/*"]
    }]
  }
}
Android assetlinks.json

Must be served at https://myapp.com/.well-known/assetlinks.json with SHA-256 fingerprint of release certificate.

[{
  "relation": ["delegate_permission/common.handle_all_urls"],
  "target": {
    "namespace": "android_app",
    "package_name": "com.myapp",
    "sha256_cert_fingerprints": ["AB:CD:..."]
  }
}]
Interview Pitfalls

Deep Linking Myths

"Custom URL schemes can't be hijacked by other malicious apps."

False. Multiple apps on Android or iOS can register the same custom scheme (e.g. myapp://). Universal Links / App Links solve this because the OS verifies ownership via server-side SSL domain association.
