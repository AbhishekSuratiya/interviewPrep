Architecture Comparison

Old Bridge vs New Architecture Modules

Old Architecture

NativeModules (Bridge)

Requires runtime reflection via @ReactMethod, eager instantiation at app startup, and asynchronous JSON serialization over the bridge.

New Architecture

TurboModules (JSI)

Starts with a TypeScript Spec contract. Codegen generates typed C++/Java abstract classes. Instantiates lazily on first access and enables synchronous JSI method returns.

Native UI Rendering

Fabric Components

Wraps native iOS/Android SDK view instances (e.g. camera, map, canvas), exposing type-safe props and events directly to React layout.

TurboModule Workflow

TypeScript Spec & Kotlin Implementation

// 1. NativeMultiplyModule.ts (Spec)
import type { TurboModule } from 'react-native';
import { TurboModuleRegistry } from 'react-native';

export interface Spec extends TurboModule {
  multiply(a: number, b: number): number; // Synchronous JSI!
}

export default TurboModuleRegistry.getEnforcing<Spec>('MultiplyModule');

// 2. MultiplyModule.kt (Android Kotlin Implementation)
class MultiplyModule(reactContext: ReactApplicationContext) 
  : NativeMultiplyModuleSpec(reactContext) {

  override fun getName() = "MultiplyModule"

  override fun multiply(a: Double, b: Double): Double {
    return a * b // Synchronous return directly to JS via JSI
  }
}
